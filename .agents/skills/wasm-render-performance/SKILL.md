# Renderer performance experiments

Use this skill for renderer optimization and capacity/regression measurements. Keep [frame-pipeline](../frame-pipeline/SKILL.md) for resource/pass invariants and [parallel-work](../parallel-work/SKILL.md) for ownership. Read [the protocol and commands](../../../docs/RENDER_PERFORMANCE.md) and [current experiment state](../../../docs/performance/STATE.md) before running.

1. Identify source HEAD/dirty hashes, verified release WASM/SDK, production package and actually served bytes separately. Freeze the baseline before changes with `VERIFY_WASM_PROFILE=release node scripts/freeze-render-build.mjs output/perf/baseline`. This refuses an existing destination and verifies source/package stability. Keep the live Quest package intact.
2. Use the maintained `scripts/benchmark-core.mjs` entry point or its `scripts/render-performance.mjs` driver. Run `--help`, then smoke. Calibrate one workload axis on the baseline; save configuration and limits. Reuse the exact selected loads on the candidate.
3. Profile the limiting workload. Check actual visible instances/commands/triangles and real resource creations; a declared object count is insufficient. Separate frame interval, RAF CPU, named CPU scopes, asynchronous valid GPU samples, cut handlers and cut completion latency. WebGPU uses the native sampled pass profiler; desktop WebGL adds bounded asynchronous EXT timer queries around application RAF commands. Neither scope proves compositor latency. Use the maintained `scripts/benchmark-rim-cuts.mjs` for separate worker/installation/commit evidence. Missing metrics are null/unavailable.
4. Inspect the exact reference renderer version and relevant implementation before porting a technique. Record the source locations, work removed, independent oracle and acceptance/rejection evidence; see [the Three transfer journal](../../../docs/performance/THREE_TRANSFER_2026-10-25.md). Reuse already published transform data before inventing another cache; preserve general inverse-transpose normals for hierarchy shear and singular fallbacks. Change one hypothesis at a time. Preserve quality, draw ordering, pass/eye ownership and cleanup. Run affected correctness/pixel checks against an independent path before measuring.
5. Run alternating baseline/candidate repetitions (default three pairs, 8s warmup/25s measurement), including explicitly asserted profiler-off controls. Retain each run, unfavorable samples and failure reasons. A capped60Hz control does not measure throughput; use baseline-calibrated near/over-budget loads.
6. Accept, revise or revert based on matched work, correctness, resource use and per-run distributions. Never sum CPU/GPU scopes into a fabricated frame cost. Label synthetic fragment stress separately from gameplay, and desktop/simulated XR separately from Quest.
7. Update compact versioned experiment evidence and STATE.md, link raw compressed data, record rejected hypotheses and the next experiment. Keep MEMORY.md a short index. Validate this skill and rerun its smoke/regression workflow from a fresh process.

No busy-wait, forced GPU completion or synchronous readback inside timing. Resolution is an explicit diagnostic axis, never an unlabelled quality reduction. Investigate the actual local Three version/materials/AA/XR settings before declaring a matched cross-engine comparison. Use the release/push gates in AGENTS.md only when their scope applies; this skill grants no publication permission.

## Integration and regression traps

Use the [nine-batch final report](../../../docs/performance/next-render-cycle/FINAL_REPORT.md), [fixed B9 protocol](../../../docs/performance/next-render-cycle/batch-9/PROTOCOL.md) and its command/results manifest as the current cycle evidence. Historical batch reports retain their own build identities and limitations; do not quote their test counts as fresh verification.

- Exact prepared-plan hits must skip group/payload construction, not only uploads. Key exact view/pass/eye and all actual input dependencies; mutable buffer content needs epochs in addition to handle identity. Keep bounded slots. Fine reuse separates compatibility, payload changes and fresh per-view culling/depth selection. Never round camera matrices or retain stale visibility. Test camera/sparse/all-moving workloads against cache-off plus independent culling-off references, including asymmetric eyes and order-sensitive barriers.
- Exercise translation16B/full112B transitions, negative/nonuniform scales, geometry/material/pipeline changes, poses and actual worker cuts. Color-free rigid layouts require **every effective RGBA component exactly finite white**, with colored/skin/morph fallback. Keep the original interpolator unless independent pixels justify removing it: the attempted varying removal failed strict XR pixels. Color/index layout and strip index format belong in pipeline/cache identities; texture masks alone are insufficient. Uint16 is portable here only for actual normalized max index ≤65534;65535 uses Uint32 because of restart rules. Padding never changes logical count. Point/line shadow pipelines must keep zero depth bias (the B6 validation repair); original-U32 oracles use that same valid pipeline. Keep original CPU cutting geometry.
- Pool inactive capacity separately from active ownership. Enforce one total budget, track active/inactive/leased/retired bytes and actual API creates, preserve view/pass/layout ownership, invalidate references on eviction, and retain leases across prepared/submitted work. Test many→few→zero→many, clear/dispose/reload and simulated XR reentry. Engine-accounted retention is not physical GPU memory or immediate driver deallocation. Warm zero creates in static scenes do not establish dynamic allocation behavior.
- Keep rejected opaque depth reordering and published-count reuse removed; fewer commands/lower callback time can still reduce throughput. Shared-GL XR is explicit opt-in: asymmetric stress improved but ordinary symmetric callback time regressed. Keep canvas-transfer default, WebGPU staging unchanged, and physical opaque-FBO/context-loss/Quest acceptance separate. The B4 crowded moving-WebGPU strict-image discrepancy remains open unless independently resolved; later gate passes do not erase it.

## Reproduce without weakening evidence

Run the maintained CLI from a fresh process and use a **new output directory**; existing evidence is now rejected rather than overwritten. `node --test tests/render-performance-output.test.mjs` checks that refusal before browser/server activity. Main clean comparisons use the frozen calibration configuration with `--warmup 8000 --sample 25000 --pairs 3 --no-profile`; dynamic and pool cases in B9 deliberately sample longer. Check actual `profiling:false` and separate query-creation observations, not merely the requested flag. Never convert a 60Hz cap into a throughput claim; increase real scene work within a bounded baseline-only calibration and freeze it for both versions.

Use `node scripts/benchmark-cold-variants.mjs --baseline-root BASELINE --candidate-root FINAL --out NEW_DIR` for fresh-page load/first-post-load/warm variant evidence. Asset load can render before its promise resolves; this is not guaranteed first-asset-draw timing or an OS/driver-cold compilation benchmark. The page captures immediately after the actual engine callback, outside timing. Retain initial failed probe attempts and repairs.

For Three, pin the actual vendored version/hash and reuse its existing per-part instancing. Record actual GLBs/poses/camera/resolution, AA, light/shadow/fog/tone/post settings, submitted commands/triangles and culling differences. `rim-common` is an explicitly limited common base-color profile, not production PBR/gameplay parity; production Rome comparison remains separately labelled when AA/shaders differ. Never slow Three artificially or replace instancing with clones to favor our engine.

Retain full frame/callback series, p95/p99/max, warm allocation events and worker-handler/install/request-to-publication latencies separately. A later visual effect is not automatically better response. GPU timestamps/GL elapsed queries describe their documented command interval, not GPU busy time, cross-context compositor cost or CPU compute. Keep unavailable/invalid values null. Record actual browser/hardware, per-run AC/battery/thermal status and concurrent GPU processes without terminating foreign work. Read power in the same host execution context as the runner: B9 simultaneous sandbox calls incorrectly suggested AC while host calls reported battery. Different contexts do not establish a physical transition; discrete endpoints are not continuous monitoring. Power transitions/contention limit causal attribution, especially for small deltas. Keep failed exact pixels and adverse runs; never loosen references/tolerances for passage.
