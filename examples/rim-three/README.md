# Three.js reference scene

This is the frozen browser reference for the Rim static-drone renderer workload. The original app files were copied from `output/rim-stress/three-reference/examples/rim/`; their source identity and per-file hashes are recorded in `output/rim-stress/three-reference/identity.json` (origin: `/Users/Honza/Documents/Codex/2026-10-22/ude/outputs/anticke-mesto/dist`). The app entry is renamed to `app.js`; `main.js` adds the optional stress controls/load adapter, and the existing VR panel adds a load count/representation line. The SDK TypeScript project excludes this independent, untyped third-party reference; browser acceptance checks its actual output separately. The bundled Three.js files retain their upstream license at [`vendor/LICENSE-three.txt`](vendor/LICENSE-three.txt).

Open this page on the same HTTPS server as the native Rim page. The default is zero added models; a convenient comparison link is `?stress=32&representation=instanced`. The selector stores both values in the query string so refresh preserves the chosen workload. `objects` clones the source node tree while sharing geometry and materials; `instanced` uses `THREE.InstancedMesh` batches.

The reference load is a static `Idle@0` pose. It does not exercise animation updates, physics, or AI. Three uses WebGL2 with antialiasing enabled and a capped device pixel ratio; the native renderer's antialiasing and XR paths differ. The reference is therefore a controlled scene/workload aid, not a claim of pixel, feature, or performance parity. Its VR debug panel shows FPS, actual calls/triangles and the requested load/representation; GPU timestamps remain unavailable.
