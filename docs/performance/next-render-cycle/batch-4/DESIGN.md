# Bounded pass/view instance resources

Keep the existing `(normalized PipelineKey, view_slot)` ownership. Lighting program classes normalize only storage-compatible material layout; pass/attachment/clipping/pipeline fields and view slots remain separate. No global camera-key map, cross-eye loans, cached image, GPU wait or buffer destroy was added.

A vector's active prefix is separate from retained page tails. Streams remain when temporarily unused or over stream admission limit. Stream and standalone mirrors stay separate. Standalone growth creates only a new vertex buffer; the page material buffer/bind group survives. Any actual buffer replacement changes its generation, invalidating fine payload slots and prepared row storage identity. Existing mutable-content epochs and exact/fine validity remain.

One64MiB known-buffer-capacity budget and4096handle budget cover all owner keys. Material Uniform bytes count; opaque bind-group driver bytes are unavailable, so the additional handle count bounds them indirectly. Defaults/limits are Rust-owned, with optional thin SDK configuration. Stream admission defaults16MiB, clamp to device max, 16B aligned; lowering it deterministically exercises standalone fallback without quality changes.

Pressure checks are O(1) while under budget. When over budget, visit owners in last-access order and evict inactive tails, idle streams and dormant standalone buffers. One-frame protection covers an eye/pass not visited yet this frame. A currently active prefix/stream and externally pinned prepared rows are never forcibly destroyed. Active, one-frame-protected or pinned working sets can exceed the retention budget, explicitly counted as over-budget events; arbitrary active rendering cannot be bounded by dropping visible geometry. Once inactive/unpinned, they are evictable. Slot-local exact/fine invalidation on eviction prevents a hidden cache from keeping unused pooled resources alive indefinitely.

Every created native instance buffer/material bind pair gets an Rc lease after the actual native create call. Map ownership and every cloned PreparedDraw/InstanceBinding carry the same lease. Last engine-lease drop updates release counters. `retiredBytes` is live leased bytes minus bytes in pool maps, e.g. buffers replaced while still pinned by prepared commands. wgpu can defer actual backend destruction until submitted commands finish; there is no physical GPU-release timestamp. Bind groups keep the material lease alongside their buffer. This is ownership instrumentation, not queue completion instrumentation.

Pool resources contain transforms/uniform values, not asset textures/geometry. Partial asset removal invalidates owning prepared rows while generic reusable pages can remain bounded. Removing the final model, scene.clear and renderer disposal release pool maps/caches; independently held command/row owners retain safe ownership until dropped. Cumulative creation/release counters persist across scene.clear; gauges return to zero when the last engine owner drops. No CPU Vec capacity is counted as a GPU create call.

## Counter units

`reuses` counts actual preparation acquisitions of an existing page/stream; an exact-plan hit bypasses acquisition and is counted by the existing plan cache instead. `evictions` counts removed page/stream/dormant-buffer slots, not individual native handles. `overBudgetEvents` counts pressure checks that still end over budget (possibly multiple passes/frames in one episode). Buffer/bind creation/release counters and byte totals are cumulative; gauges are snapshots. Retired bytes can remain pinned by prepared rows outside the pool maps. Actual GPU API allocation commands, physical allocation, and last engine ownership release are distinct observations.
