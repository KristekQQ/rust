First freeze and measure instrumentation before introducing the cache. Six exclusive opt-in CPU-wall phases separate eligible selection, grouping, basis proof, payload packing, PreparedDraw/temporary assembly, and resource/pipeline/upload setup. The sixth phase prevents attributing GPU API setup to record allocation. Disabled profiling makes no stage clock reads; cumulative stage totals are available only after timed preparation calls. Stage durations are not GPU time or on-core CPU computation.

Hypothesis: retaining the unchanged opaque plan can eliminate group/payload/record rebuilds rather than merely suppress uploads. Transparent preparation keeps its ordered uncached path. Retain immutable prepared records through reference-counted storage, not per-frame clones of each GPU handle/vector.

Conservative validity: exact scene revision, ordered visible model IDs/generations and semantic reorder flags, actual model-update revision, exact camera/VP/culling, full pipeline key (formats, winding, clipping, mask, shadow/light class), diagnostics mode and actual mutable GPU-resource content generation. Model geometry/material resources are immutable per generation; upload/replacement, pose/root/options updates and removal/clear invalidate. Every glTF mutable buffer write advances a content epoch; another pass cannot validate an older plan just because handles are identical. No rounded matrices or camera-key map growth.

Bounded fixed pass/view slots with a global retained CPU element-storage budget; unsupported slots/oversize plans fall back. Full shader/global uniforms still update and every real draw still executes. Existing submission/eye ownership remains unchanged. Coarse motion invalidation is intentional; finer invalidation is batch3.

Observe hits/misses/reasons, retained element bytes, resource generations and actual submissions/uploads. Keep adverse outcomes. Implementation details: 64 fixed slots, 16MiB retained CPU element-storage budget, exact IEEE754 bit keys, one immutable Rc<Vec<PreparedDraw>> per retained plan. Existing instance GPU pages/streams remain owned by their original pass/view keys. The global glTF content epoch advances on every write_buffer; different-view content writes conservatively miss. Input updates invalidate all plan references once; already empty cache invalidation does not rescan slots per moving model. Transparent draws stay on the original ordered path. Camera-list validation still collects/checks visible model identities on each lookup; this is not a claim of zero total preparation work.

Diagnostics: preparedPlanCache contains hits/misses, named reason arrays, retained slots/element bytes and input/content epochs. Reason arrays include explicit clear events (inputs, diagnostics, lifecycle, toggle) and lookup miss reasons; they are not a partition of misses. Retained-byte estimate covers allocated model-key/draw/diagnostic-record elements plus entry size; fixed slot metadata and existing referenced GPU allocation sizes are separate. Stage totals are opt-in cumulative wall milliseconds; prepareTimedCalls counts full timed rebuild preparations. Hit paths publish zero rebuild-stage histories, not fabricated old cold values. Lookup/model-list validation remains in the parent gltf.queue CPU scope.
